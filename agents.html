Connect source-linked regulatory records to research and financial workflows through typed MCP tools. Query jurisdictions, compare obligations and explore directed corridors with the provision, legal status, date and dataset version attached.

40 typed MCP tools  ·  one schema-validated dataset.json  ·  Apache-2.0  ·  self-hosted, no account and no key

built for regulatory research

Regulatory research depends on the exact instrument, the relevant date and the direction of a cross-border flow. CBSR makes those details available as structured records.

Each response connects the analysis to its source and release. Researchers can inspect the underlying material; developers can preserve the same context in their applications.

The record behind each response

This illustrative compose() response shows how a corridor classification travels with its supporting provision, commencement status and release identifiers.

// compose(origin="EU", destination="US", as_of="2026-08-20")
{
  "corridor":      "EU>US",
  "class":         "T",                  // regime in transition
  "mechanism":     "commencement_pending",
  "binding_at":    "destination_inbound_gate",
  "provision":     "GENIUS Act §18",
  "status":        "enacted_not_commenced",   // NOT citable as current law
  "resolves_on":   "2027-01-18",
  "resolves_to":   "II",
  "claim_class":   "tier1_legal",
  "evidence_tier": "resolution_text",
  "as_of":         "2026-08-20",
  "register":      "v0.11.0",
  "doi":           "10.5281/zenodo.20730358"
}

The example is illustrative; consult the register schema for field definitions. status distinguishes enacted legislation from provisions already in force.

Date of analysis

as_of identifies the date used to evaluate the record and its applicable legal status.

Precise source

The instrument and article provide a direct route to the primary text for checking the analysis.

Commencement status

A named field records whether the instrument is in force, pending commencement or at another stage.

Reproducible reference

The dataset version identifies the record used. Check the repository for the corresponding archive identifier.

40 typed tools over one record

The register ships as a schema-validated dataset.json with an MCP server for agent access. Typed arguments and returns support consistent integration across research tools.

Tool family What an agent does with it Key fields returned
compose() Evaluate an origin → destination corridor at a specified date. class · mechanism · provision · as_of
compose(as_of=…) Evaluate the same corridor at another date, applying the scheduled legal commencements recorded in the dataset. resolves_on · resolves_to · trigger
citable_law() Return only the strict subset that clears all six gates and may be cited as current binding law. Structural candidates are not included. claim class · source tier · review status
jurisdiction Pull one jurisdiction across every dimension: issuance, redemption, reserves, investor gating, AML, cross-border, and the rest. 15 dimensions · per-record sourcing
dimension Cut one dimension across every jurisdiction. This is the shape of “who prohibits yield and who does not”. 12 jurisdictions · comparability notes
backlog Retrieve record-level review tasks and the supporting information needed to resolve them. per-cell worklist · what is missing

Four controls for reliable integration

The data model preserves four distinctions that matter in regulatory workflows: legal effect, direction, claim type and time.

01

Track legal effect

status records commencement separately. The citable subset excludes records marked enacted_not_commenced.

02

Preserve direction

The dataset evaluates origin → destination edges separately. In this snapshot, 56 of the 66 jurisdiction pairs differ by direction.

03

Distinguish claim types

claim_class distinguishes legal propositions from market observations, preserving the purpose and evidential basis of each record.

04

Keep the date and version

Every corridor response carries as_of and the register version so later reviewers can identify the material used.

Keep these fields in downstream outputs so the source context remains available throughout the workflow.

integration

Self-host the MCP server. Code is available under Apache-2.0 and data under CC-BY-4.0.

01

Pin a version

Pin a release and retain its archive identifier. This keeps the material used by your application identifiable over time.

02

Mount the MCP server in your agent

Use the configuration and tool definitions in MCP_SERVER.md to connect the server to your agent.

03

Require the envelope in the answer

Include provision, status, as_of and version in regulatory responses. Retrieve missing fields from the tool before presenting a conclusion.

04

Respect review status

Use record-level sourcing and review status to determine how material can be presented. Refer unresolved questions to the published review worklist and primary sources.
