Querying the register from software

Software can read the register through typed MCP tools. Returned records retain fields for the provision, legal status and date analysed. Together with the dataset version in use, these fields let readers trace the records to their sources.

40 typed MCP tools  ·  one schema-validated dataset.json  ·  Apache-2.0  ·  self-hosted, no account and no key

built for regulatory research

Regulatory research depends on the exact instrument, the relevant date and the direction of a cross-border flow. CBSR makes those details available as structured records.

Whoever reads the record can check it against the cited provision.

Example corridor lookup

This excerpt from corridor_directed() in v0.11.0 shows a corridor classification, the basis for it, its commencement status and the date analysed.

// corridor_directed(origin="EU", destination="US")
{
  "edge": "EU->US",
  "class_code": "T",
  "class_basis": {
    "rule": "destination_in_transition",
    "binding_status": "made_not_commenced",
    "evidence_tier": "mixed",
    "record_ref": "us-pss-monetary_sovereignty-001"
  },
  "as_of_timeline": {
    "today_class": "T",
    "as_of_base": "2026-06-30"
  }
}

Some fields are omitted. made_not_commenced means the provision has been made and is awaiting commencement.

Date of analysis

as_of_base identifies the base date of the corridor timeline.

Precise source

The instrument and article provide a direct route to the primary text for checking the analysis.

Commencement status

A named field records whether the instrument is in force, pending commencement or at another stage.

Reproducible reference

The dataset version identifies the record used. Check the repository for the corresponding archive identifier.

40 typed tools over one dataset

The MCP server reads from a schema-validated dataset.json. The table shows selected tools.

Tool family Purpose Key fields returned
corridor_directed() Read the published classification and timeline for an origin-to-destination corridor. class_code · class_basis · as_of_timeline
compose_corridor(as_of=…) Compute a corridor classification for a specified date using the dataset's scheduled commencements. computed_class · rule · as_of
citable_law() Return records that clear all six gates for citation as current binding law. records · count · structural_candidate_count
jurisdiction_profile() Read all records for one jurisdiction, ordered by regulatory dimension. jurisdiction · record_count · records
compare_dimension() Compare records in one regulatory dimension across jurisdictions. dimension · jurisdiction_count · records
verification_worklist() Retrieve record-level review tasks and the supporting information needed to resolve them. items · count · tier_requirements

Review status in v0.11.0

In v0.11.0, no record has a current source check or an independent second review. The decision-ready subset is empty, so citable_law() returns an empty list of records.

Four distinctions the data keeps

The data model keeps four distinctions that matter when a rule is applied. These are legal effect, direction, kind of claim and time.

01

Track legal effect

binding_status records the binding status of the cited instrument. Commencement is one condition for entry into the strict citable subset.

02

Preserve direction

The dataset evaluates origin → destination edges separately.

03

Distinguish claim types

claim_class distinguishes legal propositions from market observations, preserving the purpose and evidential basis of each record.

04

Keep the date and version

Keep the evaluation date returned by the tool and the register version in use so later reviewers can identify the material used.

Keep these fields in downstream outputs so the source context remains available throughout the workflow.

Running it yourself

Self-host the MCP server. Code is available under Apache-2.0 and data under CC-BY-4.0.

01

Pin a version

Pin a release and retain its archive identifier. This keeps the material used by your application identifiable over time.

02

Connect the MCP server

Use the configuration in MCP_SERVER.md to connect the server to an MCP client.

03

Keep the source fields in any output

Keep provision, status, as_of and version in any answer that relies on a record.

04

Respect review status

Use record-level sourcing and review status to determine how material can be presented. Refer unresolved questions to the published review worklist and primary sources.
